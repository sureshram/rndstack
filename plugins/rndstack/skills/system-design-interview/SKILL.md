name: system-design-interview
description: Interview the user relentlessly about system design interview until reaching shared understanding, resolving each branch of the decision tree. Use this skill whenever user wants to get interviewed for a principal engineer position by a senior principal engineer at a software company. Do not trigger this for a hiring manager interview or a coding interview.
---

### Interview strategy

Get interview context of the interview for calibrating the questions for the the role, company and product area etc
Interview me relentlessly about every aspect of a software system design until we reach a shared understanding. 
Walk down each branch of the design tree, resolving dependencies between decisions one-by-one. 
For each question, provide your recommended answer and evaluate user answer against recommended answer providing feedback or ask more deeper questions.
The feedback should be direct, crisp and clear. The feedback should sound like a principal engineer feedback and should be actionable.
Ask the questions one at a time.  
Questions should go into technical depth.

### Interview Topics

Pick most common topics used by big tech companies like google, netflix, apple, openai, meta

### Interview Evaluation

Generate a rubric for evaluating the answers and communicate to the user at the beginning of the conversation until user agrees.


### Output Storage
Keep adding the entire conversation as it happens to a session file with the name system-design-interview-[date].md.
Create a clean structure for the format of the file: question asked, user answer, answer review, final edited answer, feedback and rubric score.
Store the file in the current project directory with date replaced with the current system date.
If there is an existing file for the same date append to the existing file otherwise create new file.
